# Layer III 出力の正規化・比較仕様(Rev.3)
## 二つの検査を分ける
| 検査 | 対象 | 方法 | 合格が意味すること |
|---|---|---|---|
| A. 原本完全性 | 保存済みの原本ファイル(入力証拠、期待ファイル) | バイト単位の SHA-256 | その原本が変化していない |
| B. 科学的同等性 | 再計算で得た出力JSON | 構造化データとして読み込み、正規化して比較 | 分類・識別子・数値が科学的に同じ |
Bの合格をAの代用にしない。正準ハッシュ(`canonical sha256`)はファイルのハッシュではない。原始期待ファイル(`expected/label_reconstruction_140.json`)は上書きしない。
## 正規化(`tools/canonical_compare.py`)
- 入力は UTF-8。先頭の BOM は除去。改行 CRLF/CR/LF の違いはJSON構文解析で無関係。空白・インデントも無関係。
- **拒否**(同値とみなさない): 重複オブジェクトキー、`NaN`、`Infinity`、`-Infinity`。不正入力として終了コード3。
- オブジェクトのキー順は無関係(正準形では昇順)。配列順は保持。ラベルレコードは `(key, theta)` で照合し、順序の差は報告のみ(科学的意味なし)。
- 正準バイト列 = `json.dumps(obj, sort_keys=True, separators=(',',':'), ensure_ascii=False, allow_nan=False)` の UTF-8、末尾改行なし。
- 数値: 整数は整数、浮動小数は Python の `repr`。真偽値は数値ではない。`null`(欠損)も値として一致が必要(`y_rebuilt` と `chir` の `null` は「再構成不能」を意味し、71件/20件)。
## 比較基準
- ラベルファイル(140レコード): 必須13フィールド(key, theta, E, y_rebuilt, y_ledger, compare, cross_consistent, source, note, ledger_state, chir, anomaly, anomaly_source)、型、レコード数140、重複・欠落なし、**全フィールド完全一致**(識別子・ラベル・`theta` を含む)。許容誤差なし。
- 解析レポート: トップレベルの `environment` を除外。数値は相対許容 **1e-9**(従来の `compare_runs.py` の基準を維持。拡大していない)。それ以外(文字列・真偽値・型・キー集合・配列長)は完全一致。
## 追加テスト(`code/tests/test_canonical_compare.py`、17件)
キー順のみ違い / 空白・改行(CRLF・BOM・インデント)のみ違い → 同値(成功)。分類ラベル変更、必須フィールド欠落、レコード欠落、レコード重複、型の相違、`theta` の微小変更、許容範囲を超える数値差、キー欠落、非有限値、重複キー → 失敗または拒否。許容範囲内の数値差(1e-12)→ 成功。いずれも検査の無効化ではなく、データ差の検出で判定する。
